# Shared-hosting deployment

KARAKO is two Laravel applications. Deploy `holding/` and `tourism/` separately. This guide assumes a typical shared account: PHP, MySQL or MariaDB, FTP or a file manager, and a panel that can create databases, cron jobs, and TLS certificates.

Do not assume SSH, root access, Redis, Supervisor, or a process that stays running. Where a command is shown, run it from the panel’s terminal, from a one-off cron entry, or on your own computer before upload. Remove a one-off cron entry after it has run.

These steps do not promise search rankings. They publish the pages with the technical SEO the applications already render.

## What must stay off the web

The domain document root may contain only the files that belong in Laravel’s `public/` directory: `index.php`, `.htaccess`, `build/`, `favicon.ico`, `robots` is generated by the app, and the `storage` symlink or directory for published images.

The following stay outside that directory:

- `.env`
- `app/`, `bootstrap/`, `config/`, `database/`, `resources/`, `routes/`, `tests/`, `vendor/`
- `storage/` except the published copies under the public disk

If a visitor can open `/.env` or `/vendor/autoload.php`, the document root is the project root. Stop and use one of the layouts below.

## Requirements

| Requirement | Value |
| --- | --- |
| PHP | 8.2. The Composer platform in both apps is 8.2.28. PHP 8.3 can run the code, but do not deploy syntax that 8.2 rejects. |
| PHP extensions | `ctype`, `curl`, `dom`, `fileinfo`, `gd`, `intl`, `mbstring`, `openssl`, `pdo`, `pdo_mysql`, `tokenizer`, `xml`, `zip` |
| Database | MySQL 8 or MariaDB 10.6 or newer, `utf8mb4` / `utf8mb4_unicode_ci` |
| Composer | 2, on a machine that matches the host PHP minor version when `vendor/` is uploaded |
| Node.js | 22, only on the build machine. The host does not run `npm`. |
| TLS | A certificate from the panel. Set `APP_URL` to the `https://` origin. |

`gd` is required. Uploaded images are re-encoded with it. `intl` is required for multilingual URLs and mail addresses.

Unused on this host: Redis, Memcached, Supervisor, a queue worker, FFmpeg, and Node.

## 1. Create the databases

In the panel, create one database and one user per application. Give each user privileges only on its own database. Use a long password generated by the panel. Store it in that app’s `.env` on the server and in your password manager. Do not put it in git, in this file, or in a seeder.

| Application | Suggested database name |
| --- | --- |
| Holding | `karako_holding` |
| Tourism | `karako_tourism` |

The panel often prefixes the account name. Use the full names the panel shows in `DB_DATABASE` and `DB_USERNAME`. `DB_HOST` is often `localhost` or `127.0.0.1`. If the host uses a socket only, set `DB_HOST` to the host the panel documents and leave `DB_SOCKET` unset unless the panel requires it. Laravel reads the standard `DB_*` variables.

Collation: `utf8mb4_unicode_ci`.

## 2. Install PHP dependencies

On a computer with PHP 8.2 and Composer 2:

```bash
cd holding
composer install --no-dev --optimize-autoloader
php artisan karako:prepare
```

Repeat in `tourism/`. `composer install` only builds `vendor/`. `karako:prepare` fills `APP_KEY` when `.env` has none, and creates `public/storage` as a relative link to `../storage/app/public`. Run it once in each application. A later run leaves an existing key untouched.

Upload the resulting `vendor/` directory with the application. Do not run `composer update` on the server. `composer install` without `--no-dev` also works, and it adds PHPUnit and the other development packages to the zip. Prefer `--no-dev --optimize-autoloader`.

Zip on the computer, then upload with the file manager. Include `vendor/` and `public/build`. Exclude `node_modules/` and `.git/`. Keep the server `.env` and `storage/app/` on later uploads; the first upload is the one that carries the generated key. Use a zip tool that stores symlinks (`zip -r -y` on Linux or macOS). The relative `public/storage` link then works on the host without a support ticket.

If the zip tool drops the link, add one cron entry, let it run once, and delete it:

```text
php /home/account/apps/holding/artisan karako:prepare
```

Use the tourism path for the tourism app, and the panel’s PHP 8.2 binary if `php` is not 8.2. That creates the link on the server. It does not need a ticket.

If the panel provides Composer on PHP 8.2, you may run the same `composer install` there instead of uploading `vendor/`.

## 3. Build the front-end assets

On the build machine, in each application:

```bash
npm ci
npm run build
```

This writes `public/build`. That directory is gitignored. Upload it. The public pages are server-rendered Blade. They do not load a JavaScript framework or a font CDN. The built CSS includes the bundled fonts.

## 4. Choose a document root

Hostnames below are examples. Set `APP_URL` to the real origin, including `https://`.

### Preferred: point the domain at `public/`

```text
example.com          -> /home/account/karako/holding/public
travel.example.com   -> /home/account/karako/tourism/public
```

The rest of each application sits next to `public/` and is not the document root. Leave `KARAKO_PUBLIC_PATH` unset.

### When the panel cannot change the document root

Keep the Laravel project outside the web root and copy only the contents of `public/` into the directory the panel already serves.

```text
/home/account/apps/holding/          full holding application, not web-accessible
/home/account/public_html/           contents of holding/public

/home/account/apps/tourism/          full tourism application, not web-accessible
/home/account/travel/                contents of tourism/public, if that is the subdomain root
```

After each deploy, replace the web-root files with a fresh copy of `public/` (`index.php`, `.htaccess`, `build/`, and the other public files). Do not copy `.env`, `vendor/`, `storage/`, or `app/` into the web root.

Edit the web root’s `index.php` so the three paths point at the application directory. For the holding example above, that file becomes:

```php
if (file_exists($maintenance = __DIR__.'/../apps/holding/storage/framework/maintenance.php')) {
    require $maintenance;
}

require __DIR__.'/../apps/holding/vendor/autoload.php';

$app = require_once __DIR__.'/../apps/holding/bootstrap/app.php';
```

Leave `$app->handleRequest(Request::capture());` as it is. Adjust `../apps/holding` to the real relative path. Do the same for tourism with its own directory. Do not commit that edited `index.php` over the repository copy; the repository copy expects `public/` to stay inside the application.

In the server `.env` set:

```text
KARAKO_PUBLIC_PATH=/home/account/public_html
```

Use the tourism web root for the tourism app. This is an absolute path. `php artisan karako:prepare` and the Vite manifest then use that directory. Rebuild the config cache after changing it.

## 5. Environment

Copy `.env.example` to `.env` on the computer you build from, or let `php artisan karako:prepare` copy it. Generate a key once per application:

```bash
php artisan karako:prepare
```

That command writes `APP_KEY` only when the line is empty, and it also creates the storage link from the next section. Use a different key for holding and tourism. Do not run `key:generate --force` on an application that already has sessions or encrypted values.

After the files are on the host, open `/setup` once in the browser. On the holding domain that is `https://example.com/setup`, and on the tourism domain it is the same path. Laravel refuses to start when `APP_KEY` is empty, so the application writes that key while it boots, before the page runs. The page then runs `migrate --force` and `storage:link`. Holding also seeds the nine divisions the first time that table is empty. When `APP_KEY` is already filled, the page leaves the key. Do the same on the other domain. The `.env` file must be writable by PHP.

Production values that matter:

| Variable | Production |
| --- | --- |
| `APP_ENV` | `production` |
| `APP_DEBUG` | `false` |
| `APP_URL` | `https://` plus the real host, no trailing slash |
| `APP_KEY` | unique to this application |
| `DB_CONNECTION` | `mysql` |
| `DB_*` | the database created in step 1 |
| `SESSION_DRIVER` | `file` |
| `CACHE_STORE` | `file` |
| `QUEUE_CONNECTION` | `sync` |
| `LOG_LEVEL` | `error` or `warning` |
| `TOURISM_URL` | holding only: `https://` origin of the tourism site, or empty |
| `HOLDING_URL` | tourism only: `https://` origin of the holding site, or empty |
| `MAP_TILE_URL` | tourism only: tile template, or empty |

When `APP_URL` starts with `https://`, the application generates `https` URLs and marks the session cookie secure, including when the panel terminates TLS and PHP itself sees a plain HTTP request.

Leave `SESSION_SECURE_COOKIE` unset in that case. The application sets the secure flag from `APP_URL`.

`APP_DEBUG=true` shows stack traces to visitors. Keep it `false` on a public host. For a single failed request, you may turn it on, reload the failing URL, write down the message, and turn it off again. Do not leave it on.

Do not commit `.env`.

## 6. Migrate, seed, and create an administrator

From the application directory (`holding/` or `tourism/`, not the web root):

```bash
php artisan migrate --force
```

Holding only, the first time:

```bash
php artisan db:seed --force
```

That seed writes the nine division titles and the default navigation. It does not create a user and it does not contain a password. Tourism’s seeder is empty. Enter tours and other tourism records in the admin.

Indexed string columns are 191 characters. On a shared host, a `utf8mb4` index is limited to 1000 bytes, and `varchar(255)` is 1020 bytes, so MySQL rejects the primary key. If `/setup` stops after creating `users`, upload this version and open `/setup` again. Tables that already exist are left in place, and the remaining tables are created.

Create the first administrator without putting the password in the command, so it is less likely to land in shell history:

```bash
php artisan karako:admin you@example.com
```

The command prints a generated password once. Store it in a password manager, sign in at `/admin`, and do not paste it into a README, a ticket, or git. If the console output was visible to other people, sign in and change the password. Repeat the command in the other application with its own email. The two user tables are not shared.

`--password=` exists for a non-interactive run. Prefer the generated password.

On a host without a terminal, opening `/setup` already runs `migrate --force` and, for holding, this seed the first time the divisions table is empty. `/setup` does not create an administrator. `karako:admin` still needs the panel terminal or a one-off cron entry.

## 7. Storage and permissions

These directories must be writable by the PHP user:

- `storage/`
- `bootstrap/cache/`

On a typical panel, `755` for directories and `644` for files is enough when PHP runs as the account user. If uploads or `config:cache` fail with a permission error, set `storage/` and `bootstrap/cache/` to `775`. Avoid `777` unless the panel’s PHP user is different and the host documents no other option.

Published images go to `storage/app/public`. Create the public link:

```bash
php artisan karako:prepare
```

`karako:prepare` creates that link with a relative target, `../storage/app/public`, so the same link works after upload. Running it again does nothing when that link is already in place.

### When the host refuses symlinks

`karako:prepare` prints an error and does not create `public/storage`. Use a real directory instead:

1. Create a `storage` directory inside the web root (`public/storage`, or the copied web root’s `storage`).
2. Make it writable by PHP.
3. Set `FILESYSTEM_PUBLIC_ROOT` in `.env` to that directory’s absolute path.
4. Run `php artisan config:cache` again.

New uploads are then written directly into the web root. `public/.htaccess` refuses to execute `.php`, `.phtml`, and `.phar` files under `/storage`. On Nginx, which ignores `.htaccess`, add a deny rule for those extensions under `/storage`.

Keep a copy of older uploads if you switch this path later. Files already stored under `storage/app/public` are not moved automatically.

## 8. Cache the configuration

After `.env` is final:

```bash
php artisan config:cache
php artisan route:cache
php artisan view:cache
```

`config:cache` freezes environment values. Changing `.env` has no effect until you run `php artisan config:cache` again (or `php artisan config:clear` while debugging).

`route:cache` is safe for these applications: the HTTP routes do not use closures.

## 9. HTTPS

Issue the certificate in the panel (Let’s Encrypt or the host’s certificate) for each domain. Redirect HTTP to HTTPS in the panel. Set `APP_URL` to the `https://` origin and rebuild the config cache.

The applications send:

- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: SAMEORIGIN`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Permissions-Policy: camera=(), microphone=(), geolocation=()`

They do not send a Content-Security-Policy. The public pages include inline JSON-LD, and a strict policy would block it.

The applications do not trust every proxy. Rate limits use the connecting address. If every visitor appears as one proxy address, the shared limit can trip for everyone. Set trusted proxies only if you know the proxy ranges; do not set them to `*`.

## 10. Cron and queues

Nothing in the current applications is scheduled. You do not need a cron entry for the sites to serve pages, accept forms, or save admin edits.

`QUEUE_CONNECTION=sync` runs work inside the web request. There is no worker to keep alive. Mail, when you later choose a mailer, will send during the request. A slow SMTP server will slow that request. Do not switch the queue to `database` or `redis` unless you also have a way to run `php artisan queue:work`, which this host is not assumed to provide.

If a later release adds a scheduled task, one cron entry is enough:

```text
* * * * * php /home/account/apps/holding/artisan schedule:run
```

Use the tourism path for the tourism app. PHP CLI on shared hosts is often `php` or a versioned binary such as `php82`. Ask the panel which binary is PHP 8.2.

## 11. Backups and rollback

Back up, per application, before each deploy:

- A database dump from the panel or `mysqldump`
- `storage/app/` (uploads and local private files)
- The server `.env`, stored outside the web root and outside git

`vendor/` and `public/build` can be rebuilt. A database dump cannot.

Keep the previous application directory until the new one is checked. To roll back:

1. Put the previous files back, or point the domain at the previous `public/` directory.
2. Restore the database dump if the new release ran migrations.
3. Confirm `.env` still matches that release (`APP_KEY` must be the one that release used).
4. Run `php artisan config:cache` in the restored application.

Uploaded files and the database are a pair. Restoring one without the other leaves broken image paths or rows the code does not understand.

## 12. Updates

1. Back up the database, `storage/app/`, and `.env`.
2. On the build machine: `composer install --no-dev --optimize-autoloader`, `php artisan karako:prepare`, and `npm ci && npm run build`.
3. Upload the new code, `vendor/`, and `public/build`, without overwriting the server `.env` or `storage/`.
4. If you use the copied-public layout, copy `public/` into the web root again and re-apply the `index.php` path edits.
5. `php artisan migrate --force`
6. `php artisan config:cache && php artisan route:cache && php artisan view:cache`
7. Open `/`, `/fa`, `/en`, `/admin/login`, and one public page that includes an image.

## Troubleshooting

### 403

The document root is missing an index, or the panel denies directory access. Point it at `public/` or at the copied public files, and confirm `index.php` and `.htaccess` were uploaded. Some panels hide dotfiles; `.htaccess` and `.env` must still be present in the right places (`.env` only beside the application, never in the web root).

### 404 on every page except `/`

`mod_rewrite` is off, or `.htaccess` was not uploaded. Enable `AllowOverride` if the host exposes that setting. Pretty URLs need the Laravel rewrite rules. A 404 for a single content URL usually means the record is a draft, unpublished, or has no translation in that language. That 404 is intentional.

### 500

Set `APP_DEBUG=true` only long enough to read the message, then set it back to `false` and rebuild the config cache. Common causes:

- `APP_KEY` is empty
- `storage/` or `bootstrap/cache/` is not writable
- `config.php` was cached with the wrong database password or an empty key (`php artisan config:clear`, fix `.env`, `php artisan config:cache`)
- PHP is older than 8.2, or `gd` / `mbstring` / `pdo_mysql` is missing
- The copied `index.php` still points at `../vendor` instead of the real application path

The holding and tourism logs are `storage/logs/laravel.log` in each application. Inquiry bodies are stored in the database for the team. They are not written to that log by the application code.

### Database errors

Check `DB_HOST`, `DB_DATABASE`, `DB_USERNAME`, and `DB_PASSWORD` against the panel, including prefixes. The holding app and the tourism app use different databases. A dump from one cannot be imported into the other.

### CSS, JavaScript, or images 404

`public/build` was not uploaded, or the copied web root is missing `build/`. Run `npm run build` and upload it. Image URLs under `/storage/` need `php artisan karako:prepare` (or a real `public/storage` directory plus `FILESYSTEM_PUBLIC_ROOT`). `APP_URL` must match the origin in the browser, including `https`, or asset URLs will point at the wrong host. Rebuild the config cache after changing `APP_URL`.

### Login works on HTTP and fails on HTTPS

The session cookie was not secure, or the old cookie is stuck. Use an `https` `APP_URL`, rebuild the config cache, and sign in again in a fresh browser session.

### Forms return 419

The session expired or the web root is serving two different applications under one cookie path. Each app has its own `APP_KEY` and its own session files. Stay on one host per app.

`public/robots.txt` is not part of the repository. A static file in the web root is served instead of the generated rules and will allow `/admin`. If a host or an old upload left one there, delete it. `/robots.txt` must come from the application.

### A page is indexed that should not be

`/admin` is disallowed in `robots.txt` and the admin layout sends `noindex`. Drafts return 404. Filtered tour, attraction, and feedback URLs send `noindex` and a canonical URL of the unfiltered list. Foundations, credits, and surveys send `noindex`. `robots.txt` is not an access control. Authorization still protects `/admin`.
